# SWARM: how every session works

`master_prompt.md` is the authority. Never edit it. If this file and the master prompt conflict, the master prompt wins (except for the licence, which is the owner's decision DL-001); record the conflict in `research/decision_log.md`.

## 1. Reading order (before modifying anything)

1. `master_prompt.md`
2. `roadmap.md`
3. `progress.md`
4. `research/protocol.md` (and the relevant `research/experiments/EXP-NNN/protocol.md`)
5. `research/claims_register.csv`

Then run `git status`, inspect existing files, and never overwrite owner changes. State the current milestone and the next bounded task before working.

## 2. Mandatory requirements (master prompt section 11)

- Maintain the section 11.1 tree: `research/experiment_registry.csv`, `research/paper/` (manuscript.md canonical; manuscript.tex and manuscript.pdf generated), `research/experiments/EXP-NNN/` (protocol, report, config, run manifest, metrics, figures, reproduction), `research/publication/` (artifact manifest, claims audit, reproducibility report, author review, release checklist).
- Stable IDs: EXP-NNN, run IDs, figure IDs, claim IDs. A seed is a run, not an experiment. A new question or a materially different protocol gets a new EXP ID.
- Register each experiment before confirmatory execution. Write `EXP-NNN/protocol.md` per 11.2 before running it. Freeze before evaluating held-out results; post-hoc changes are exploratory, dated and justified.
- Every registered experiment gets a standalone report with the 12-part structure of 11.3, including failed, null, abandoned and exploratory ones. Reports link to their own machine-readable outputs. Tables and figures are generated from outputs, never copied by hand.
- One integrated manuscript (11.4), 3,000 to 6,000 words where the evidence justifies it; status "independent research manuscript / preprint draft, not peer reviewed".
- Evidence pipeline (11.5): one generator for tables and figures reused by reports, manuscript, demo and articles; an artifact manifest mapping each number to experiment, runs, metric, path, script, hashes and revision; a second review pass that challenges the preferred hypothesis.
- Milestone additions (11.6): M0/M1 registry, manuscript skeleton, experiment protocols, zero-cost toolchain; M2 versioned schemas, manifests and report generators with the core; M3 reports as experiments finish, provenance captured at run time; M4 reports, audit, synthesis with contradictory results and sensitivity; M5 identical numbers across demo, paper, reports and articles; M6 compile and inspect PDFs, verify references and links, clean-clone smoke reproduction, owner review checklist.
- Toolchain (DL-002): pandoc Markdown to Typst, compiled with the `typst` Python package (pass `-V mainfont="Libertinus Serif"`); `manuscript.tex` generated by pandoc. Never claim a PDF exists that was not generated.

## 3. Rules (all sessions)

- **Gates.** Never push, add a remote, create a GitHub repository or publish anything (G-PUBLIC). No paid service of any kind. Never freeze a protocol yourself: freezing is the owner's (G-FREEZE). No confirmatory experiment before the owner freezes its protocol. Tiny exploratory smoke checks are allowed and labelled exploratory.
- **Scope.** Work only inside this repository, except read-only use of the tools in `research/feasibility.md` (`../.tools/` relative to this repository, Node at `../../helix/.tools/node/bin`, read-only, never modified). Do not touch any other folder under the research root. Never kill processes you did not start. Never delete anything you did not create in the current session.
- **Truthfulness.** Never fabricate results, citations, test counts or PDFs. Record commands and their actual outputs. Unverified means labelled unverified. Do not claim a test count or passing status without running it.
- **Files and style.** New text and code files start with `SPDX-License-Identifier: LicenseRef-SWARM-NC-Research-1.0` as a comment where the format allows; JSON and CSV are covered by `NOTICE.md`. English. No em dashes. Plain, formal register. No e-mail address, personal identifier or secret in any committed file (git author metadata excepted). Refer to the owner as "the owner" (they/them).
- **Licence.** Do not change `LICENSE`, `NOTICE.md`, `LICENSE_HISTORY.md`, `CLA.md`, `.github/`. Development commands may be appended to `CONTRIBUTING.md`. The project is source-available, never described as "open source".
- **Claims boundary.** No biological fidelity, no universal distributed-system guarantees, all simulation results labelled as simulated.
- **Commits.** Local only, with the owner's git identity passed by `git -c user.name=... -c user.email=...` exactly as given in `../_shared/M0-brief.md` (relative to this repository) (the address is not repeated here: no e-mail address in committed files). The message ends with a blank line, then the Co-Authored-By trailer given in that brief. Run `git status` before and after.

## 4. Session end

Append a dated entry to `progress.md` (commands, real outputs, failures, changed files, risks, next action); update `roadmap.md` statuses; append decisions to `research/decision_log.md`; journal any measurement in `research/experiment_journal.jsonl`.
